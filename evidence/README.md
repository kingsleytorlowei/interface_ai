## Everything else

One directory per run. Each holds a redacted `events.jsonl` (append-only, one event per line),
`result.json` (the typed run result), and `snapshots/` (redacted tree + text, and a screenshot)
wherever the engine stopped, asked for approval, or handed off. In events and results, the
run's sensitive inputs and outputs appear only as placeholders such as `«inputs.member_id»`.
Snapshots are scrubbed of those same values, but show whatever else was on screen (e.g. a
member name the capability never extracted); all data here is synthetic. Discovery runs also
keep `transcript.json` (the model's reasoning and tool calls) and `capability.draft.json`.
Since the sub-account fix, transcripts replace each screen the model saw with that
observation's digest in `events.jsonl`; the two earlier lookup discoveries predate it and
still include the screens (their undeclared data was redacted only because the lookup
extracted the member's name as an output).

## Stability measurements

`uv run cua stability <capability> [--tenant riverbend] --params ... --params ...` replays an
approved capability ten times unattended, cycling through the input sets, and writes each
run under `stability/<capability>@<version>-<timestamp>/`. The report (verdict, success rate,
consistency, drift, recoveries, durations, and each run's id) sits next to what it measured
in `catalog/`, and clears the capability for unattended replay only if it meets the app's
`unattended` thresholds.
